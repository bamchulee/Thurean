## 0. งานแรก: Deploy Apps Script (ต้องทำก่อนทดสอบอะไรทั้งนั้น)

โค้ดในชีตจริงยังเป็นรุ่นเก่า ไฟล์ที่เปลี่ยนแล้วรอ deploy:
- `4_Orders.gs`, `5_Setup.gs` — แก้บั๊กอัปเดตออเดอร์บางช่องแล้วชีตรีเซ็ต `orderStatus` / `channel` / `courier` กลับเป็นค่าเริ่มต้น
- `1_Config.gs`, `6_ReadAll.gs` — เพิ่มคอลัมน์ Orders สำหรับ flow จอง (ดูข้อ 2.5) และส่ง `grandTotal` กลับมาให้เว็บ

1. เปิด Google Sheet หลัก > Extensions > Apps Script
2. แทนที่เนื้อหาไฟล์ `1_Config`, `4_Orders`, `5_Setup`, `6_ReadAll` ด้วยไฟล์ในโฟลเดอร์ `google-apps-script/` (วางทั้งไฟล์ อย่าเหลือโค้ดเก่า ชื่อฟังก์ชันจะชน)
3. Deploy > Manage deployments > แก้ไข > Version: **New version** > Deploy (ใช้ URL เดิม)
4. รันฟังก์ชัน `setupDurianWinkinSheets` หนึ่งครั้ง (หรือกดปุ่มตั้งค่าชีตในหน้าแอดมิน > ตั้งค่า) → ชีต Orders ต้องมีคอลัมน์ใหม่ต่อท้าย ข้อมูลเดิมไม่หาย
5. ทดสอบ: แก้เลขพัสดุของออเดอร์หนึ่งในหน้าแอดมิน → `orderStatus` ในชีตต้อง **ไม่เปลี่ยน**

ถ้าแก้ไฟล์ `.gs` อีกเมื่อไร ต้องทำขั้น 2–3 ซ้ำทุกครั้ง

## 2. Flow เป้าหมาย (ยึดตามนี้)

หลักการ: **ทุเรียนต้องชั่งก่อนถึงรู้ยอดจริง → ลูกค้าจองก่อน ไม่จ่าย → แอดมินชั่ง → ค่อยส่ง QR ยอดจริง**

### 2.1 เลขออเดอร์
- เลขเดียวตลอดชีวิตออเดอร์: `OD000001` ออกตอนลูกค้ากดจอง ใช้ต่อจนจัดส่งและเคลม **ไม่มีเลขจองแยก**
- ออเดอร์เก่า `WK-9523` คงเลขเดิม ค้นหาด้วย `findOrderById()` เสมอ (รับ `OD000012`, `od12`, `12`, `WK-9523`) — ห้ามเขียน `o.id === x` หรือ regex เลขออเดอร์เอง
- รหัสสินค้าก็ขึ้นต้น `WK-` (เช่น `WK-07`) อย่าสับสนกับเลขออเดอร์

### 2.2 สถานะ (ใช้ชุดนี้ชุดเดียวทั้งระบบ)

| ลำดับ | `orderStatus` | `paymentStatus` | ใครเปลี่ยน | ลูกค้าได้รับข้อความ |
|---|---|---|---|---|
| 1 | `สั่งจอง` | `pending` | ลูกค้ากดจอง | ใบรับจอง: เลขออเดอร์, รายการ, **ราคาประเมิน (ระบุชัดว่ายังไม่ใช่ยอดจริง)**, "รอแอดมินคัดและชั่ง ยังไม่ต้องโอน" — **ห้ามส่ง QR** |
| 2 | `รอชำระเงิน` | `pending` | แอดมินชั่ง (`ชั่ง OD000012 4.2` ในกลุ่ม หรือหน้าแอดมิน) | ยอดจริง + **QR PromptPay ยอดจริง** + ปุ่ม "แนบสลิป" |
| 3 | `รอชำระเงิน` | `slip_submitted` | ลูกค้าส่งรูปสลิป | "ได้รับสลิปแล้ว รอแอดมินตรวจ" |
| 4 | `ชำระเงินแล้ว/เตรียมจัดส่ง` | `confirmed` | **แอดมินกดยืนยันสลิป** (ห้ามระบบยืนยันเอง) | "ยืนยันยอดแล้ว เตรียมจัดส่ง" |
| 5 | `กำลังจัดส่ง` | `confirmed` | แอดมินใส่เลขพัสดุ | เลขพัสดุ + ปุ่มเช็กพัสดุ |
| 6 | `จัดส่งสำเร็จ` | `confirmed` | แอดมิน (ตั้ง `deliveredAt` อัตโนมัติ) | "ได้รับของแล้ว แจ้งเคลมได้ภายใน 24 ชม." |
| — | `ยกเลิก` | คงเดิม / `refunded` | แอดมิน หรือหมดเวลาชำระ | แจ้งยกเลิก **และต้องคืนสต็อก** |

- สถานะภาษาอังกฤษเดิม (`received`, `preparing`, `packed`, `shipped`, `delivered`, `claimed`) และ `รอชั่งน้ำหนัก/สรุปยอด` = **ของเก่า** อ่านได้ (map ให้ตรงลำดับข้างบน) แต่ **ห้ามเขียนลงออเดอร์ใหม่**
- ทำฟังก์ชันกลางที่เดียว เช่น `src/lib/order-status.ts`: ชื่อสถานะ, label ภาษาไทย, ลำดับ, การ map ของเก่า, transition ที่อนุญาต — แล้วให้ admin, tracking, LINE, claim-policy ใช้ร่วมกัน (ตอนนี้แต่ละไฟล์มี map ของตัวเองและไม่ตรงกัน)
- transition ที่อนุญาตเท่านั้น: 1→2, 2→3, 3→4, 3→2 (สลิปไม่ผ่าน), 4→5, 5→6, (1|2|3)→ยกเลิก — คำสั่ง `ชั่ง` ใช้ได้เฉพาะสถานะ 1–2

### 2.3 แจ้งเตือนกลุ่มแอดมิน
ทุกเหตุการณ์ต่อไปนี้ต้องเด้งเข้ากลุ่มแอดมินพร้อมปุ่ม **postback** ที่กดจัดการในแชตได้:

| เหตุการณ์ | ปุ่มในการ์ด |
|---|---|
| ลูกค้าจองใหม่ | ✅ รับจอง · ❌ ปฏิเสธ (คืนสต็อก) · วิธีพิมพ์ `ชั่ง <เลข> <กก.>` |
| ลูกค้าส่งสลิป (แนบรูป) | ✅ ยอดถูกต้อง · ❌ ยอดไม่ตรง |
| ลูกค้าแจ้งเคลม | ✅ อนุมัติเปลี่ยนลูก · 💸 คืนเงิน · ❌ ปฏิเสธ |
| ลูกค้าเปิด ticket คุยแอดมิน | ข้อความลูกค้า + ปุ่มเปิดแชต |
| ค้างเกินเวลา (จองไม่ชั่งเกิน X ชม. / รอชำระเกิน 24 ชม.) | สรุปรายการค้าง |

- postback จากกลุ่ม **ต้องเช็กว่ามาจากกลุ่มแอดมินจริง** (`source.groupId === LINE_ADMIN_GROUP_ID`) ก่อนเปลี่ยนข้อมูลใด ๆ
- การ์ดแอดมินแสดงสถานะตามจริง ห้ามเขียน "รอตรวจสลิป" กับออเดอร์ที่แค่จอง และห้ามเรียกราคาประเมินว่า "ยอดสุทธิ"

### 2.4 สต็อก
- ตัดสต็อกตอนจอง (กันขายเกิน) **และคืนสต็อกเมื่อยกเลิก/ปฏิเสธ** ใน Apps Script ภายใต้ล็อกเดียวกัน (`updateOrder` ตอนนี้ไม่คืน)

### 2.5 ฐานข้อมูล (Google Sheets)
- **โครงสร้างจริงอยู่ที่ `SHEET_DEFS` ใน `google-apps-script/1_Config.gs` ที่เดียว** ขาดคอลัมน์อะไรเพิ่มได้เลย (ต่อท้าย อย่าลบ/ย้ายคอลัมน์เดิม) แล้วเพิ่มใน `6_ReadAll.gs` (ไม่งั้นเว็บไม่เห็น) และ `src/types/durian.ts` แล้ว deploy ตามข้อ 0
- คอลัมน์ Orders ที่เพิ่มไว้ให้แล้ว (ยังไม่มีโค้ดเขียนค่า — ให้คุณใช้ตอนทำ flow):

| คอลัมน์ | เขียนตอน |
|---|---|
| `weighedAt` | แอดมินชั่ง (1→2) |
| `slipSubmittedAt` | ลูกค้าส่งสลิป (2→3) |
| `paidAt` | แอดมินยืนยันยอด (3→4) |
| `cancelledAt`, `cancelReason` | ยกเลิก / ปฏิเสธ / หมดเวลาชำระ |
| `bookingKey` | ตอนจอง — คีย์จาก postback ปุ่มยืนยัน ถ้ามีออเดอร์ที่ key นี้แล้ว ให้ตอบใบเดิม ห้ามสร้างใหม่ (บั๊กข้อ 3.6) เช็กใน Apps Script `createOrder` ภายใต้ล็อก |

- `paymentStatus` ใหม่: `slip_submitted` (มีใน type แล้ว)
- `sheets/*.csv` เป็นแค่ไฟล์ในเครื่อง (ไม่ขึ้น git) — ไม่ใช่ที่กำหนด schema

## 3. บั๊กที่ต้องแก้ (เรียงตามความหนัก)

1. **ข้อมูลลูกค้ารั่วไปกลุ่มอื่นได้** — `webhook/route.ts` ~บรรทัด 203–208: bot เห็นข้อความจากกลุ่มไหนก็ตั้งกลุ่มนั้นเป็นกลุ่มแอดมิน → การ์ดที่มีชื่อ/เบอร์/ที่อยู่ลูกค้าไปโผล่กลุ่มนั้น
   แก้: เลิก auto-bind ทั้งตอน `join` และตอนมีข้อความ ใช้ env `LINE_ADMIN_GROUP_ID` อย่างเดียว ถ้าจะผูกผ่านแชต ให้ต้องพิมพ์คำสั่ง + รหัสลับ และบันทึกลงชีต ไม่ใช่ `/tmp`
   ลบ ID ที่ฝังในโค้ด (`sheets-db.ts` ~บรรทัด 83)
2. **คำสั่งแอดมินในกลุ่มไม่เช็กสิทธิ์** — `ชั่ง` / `สต็อก` / `ออเดอร์` ทำงานในกลุ่มไหนก็ได้ ต้องจำกัดเฉพาะกลุ่มแอดมิน (DM `ชั่ง` ~บรรทัด 1332 ต้องเช็กว่าเป็น user ที่ role admin)
3. **ส่งสลิปแล้วระบบยืนยันการชำระเอง** (~บรรทัด 2360) → ต้องเป็น `slip_submitted` แล้วรอแอดมินกด
4. **ลูกค้าได้ QR ก่อนชั่ง** — `OrderSuccessModal.tsx` บรรทัด 58 เช็กแค่ `รอชั่งน้ำหนัก/สรุปยอด`; LINE step `confirm` (~บรรทัด 811) ตอบ QR ทันที → ใบรับจองไม่มี QR (ข้อ 2.2 แถว 1)
5. **ยอดเงินสองยอดไม่ตรงกัน** — webhook คำนวณ `pricePerKg × avgWeight × qty + 120` แต่ `submitNewOrder` บันทึก `price × qty` และ push ใบสรุปอีกใบ → **ยอดเงินต้องคำนวณที่ `order-service.ts` ที่เดียว** ข้อความทุกอันอ่านจาก `order.totalPrice` / `order.grandTotal` ห้ามคำนวณใหม่ใน message builder; ค่าส่งมาจาก `shopInfo.shippingMethods` ห้าม hardcode 120
6. **กดปุ่มยืนยันอันเก่าในแชตแล้วได้ออเดอร์ซ้ำ** — postback ใส่ nonce/draft id แล้วเช็กว่าใช้ไปแล้วหรือยัง (เก็บในชีต ไม่ใช่ `/tmp`)
7. **ชั่งแล้วสถานะไม่ไปต่อ** — admin weigh modal (`admin/page.tsx` ~1402) ไม่รู้จัก `สั่งจอง`, dropdown (~2349) ไม่มีตัวเลือกนี้ → ใช้ transition กลาง (ข้อ 2.2)
8. **หลังชั่ง ลูกค้าไม่ได้ QR** — `buildCustomerStatusFlex` ไม่มี QR/ปุ่มแนบสลิป ทั้งที่ bot บอกแอดมินว่าส่งแล้ว
9. **หลังบ้านมองไม่เห็นออเดอร์ภาษาไทย** — ตัวนับและแท็บกรอง (`admin/page.tsx` ~1450, ~1717) ใช้สถานะอังกฤษ → เปลี่ยนเป็นตามข้อ 2.2
10. **ยกเลิกไม่คืนสต็อก** (ข้อ 2.4)
11. **`confirm_without_slip` หยิบออเดอร์ผิดใบ** (~บรรทัด 1158) ใช้ `userOrders[0]` ซึ่งเป็นใบเก่าสุดเมื่ออ่านจากชีต → เรียงตาม `createDate` ใหม่สุด (ที่อื่นที่ใช้ `data.orders.find(...)` หา "ออเดอร์ล่าสุด" ก็เป็นแบบเดียวกัน)
12. **สร้างออเดอร์ด้วยข้อมูลไม่ครบ** — step `confirm` ใช้ `phone`/`address` = `"-"` ถ้าไม่มีข้อมูลสมาชิก, และ fallback `data.products[0]` / `"WK-01"` เมื่อหา pid ไม่เจอ → ต้องปฏิเสธ ไม่สร้างออเดอร์มั่ว
13. **ลูกค้าเว็บส่ง `paymentStatus` / `orderStatus` / `shippingCost` / `slipUrl` มาเองได้** — `api/orders/route.ts` POST ส่ง `...raw` ทั้งก้อนเข้า `submitNewOrder` → ถ้าไม่ใช่แอดมิน ให้รับเฉพาะ ชื่อ เบอร์ ที่อยู่ วิธีส่ง รายการสินค้า

15. **`next.config.ts` ชี้ `google-apps-script/Code.gs` ที่ไม่มีแล้ว** → ปุ่ม "คัดลอกโค้ดทั้งหมด" ในหน้าตั้งค่าว่างบน Vercel ให้เปลี่ยนเป็น `./google-apps-script/*.gs`

## 4. กติกาเขียนข้อความ LINE (ข้อจำกัดจริงของ LINE — ละเมิดแล้ว API ตอบ 400 และลูกค้าไม่ได้อะไรเลย)

เคยพังมาแล้วใน commit ก่อน ๆ: label เกิน 20 ตัว, `alignItems`, `paddingHorizontal`, `margin: "xxs"`

**Flex**
- ค่า `margin` / `spacing`: `none` `xs` `sm` `md` `lg` `xl` `xxl` หรือ px เท่านั้น (**ไม่มี `xxs`**)
- `size` ของ text มี `xxs` ได้ แต่ margin/spacing ไม่มี
- padding ใช้ `paddingAll` / `paddingTop` / `paddingBottom` / `paddingStart` / `paddingEnd` (**ไม่มี `paddingHorizontal` / `paddingVertical`**)
- `justifyContent` / `alignItems` ใส่ได้ **เฉพาะ `box`** — ใส่ที่ text / button / image แล้ว 400 (ที่ component ใช้ `align` / `gravity` แทน)
- รูป: `aspectRatio` รูปแบบ `"16:9"`, URL ต้องเป็น `https`
- carousel ไม่เกิน 12 bubble, Flex ทั้งก้อนไม่เกิน ~30KB
- `altText` บังคับมี ไม่เกิน 400 ตัวอักษร

**Action / Quick reply**
- `label` ของปุ่มและ quick reply **ไม่เกิน 20 ตัวอักษร** (นับอีโมจิด้วย)
- quick reply ไม่เกิน 13 ปุ่ม
- postback `data` **ไม่เกิน 300 ตัวอักษร** — ตอนนี้ step `confirm` ยาว ~290 เพราะ encode ความสุกภาษาไทย → ใช้รหัสสั้น (`r=1`, `r=2` …) แทนข้อความไทยใน `data`
- `displayText` ไม่เกิน 300

**การส่ง**
- reply/push ครั้งละ **ไม่เกิน 5 messages**
- `replyToken` ใช้ได้ครั้งเดียว และหมดอายุเร็ว (~1 นาที) — ทำงานหนัก (เรียกชีต) ก่อน reply ต้องเร็ว ถ้าช้าให้ใช้ `fallbackUserId` ของ `replyLineMessage` เพื่อ push แทน
- 1 event ตอบครั้งเดียว — อย่าทั้ง reply ใน webhook และ push ซ้ำใน `submitNewOrder` จนลูกค้าได้สองใบ (ข้อ 3.5)
- push มีโควตารายเดือน ใช้ reply เมื่อทำได้

**น้ำเสียง**
- ภาษาไทยสุภาพ ลงท้าย "ครับ" ใช้อีโมจิพอประมาณ (🍈 📦 ✅)
- ทุกข้อความบอก **เลขออเดอร์ + สถานะปัจจุบัน + ลูกค้าต้องทำอะไรต่อ** (หรือ "ไม่ต้องทำอะไร รอแอดมิน")
- ห้ามสัญญาสิ่งที่ระบบไม่ได้ทำจริง (เช่น "ระบบเปลี่ยนสถานะให้อัตโนมัติ" ทั้งที่ไม่เปลี่ยน)
- ข้อความทุกแบบสร้างใน `line-notify.ts` เท่านั้น webhook ห้ามประกอบ Flex เอง (ตอนนี้มี bubble ฝังใน webhook หลายจุด ให้ย้ายออก)

## 5. กติกาโค้ด

- สถานะแชตหลายขั้น: **อย่าพึ่ง `line-sessions.ts` (`/tmp`)** — ทำ flow ให้ stateless (ข้อมูลอยู่ใน postback) หรือเก็บ draft ลงชีต
- ห้ามฝัง secret / token / group ID / sheet URL ในโค้ด ใช้ env (`.env.example` คือรายการ)
- **ห้าม commit ข้อมูลลูกค้าจริง** (ชื่อ เบอร์ ที่อยู่ passwordHash, รูปสลิป) ทุกรูปแบบ repo นี้ push ขึ้น GitHub — `sheets/*.csv` อยู่ใน `.gitignore` แล้ว อย่าเอาออก และอย่า `git add -f`
- ห้ามรัน `npm run sheets:push` เอง โดยไม่ได้รับอนุญาตจากเจ้าของร้าน (เขียนทับชีตจริง)
- แก้ Apps Script แล้วต้องคง schema ให้ตรงกับฝั่งเว็บ (`ID_FORMATS` ใน `1_Config.gs` ↔ `src/lib/ids.ts`) และ deploy ใหม่ (ข้อ 0)
- ก่อนจบงานทุกครั้ง: `npx tsc --noEmit` ต้องผ่าน
- commit แบบ conventional (`feat(line): ...`, `fix(orders): ...`) แยกเป็นเรื่อง ๆ

## 6. ทดสอบก่อนบอกว่าเสร็จ (ทำจริงกับ LINE OA)

1. ลูกค้าใหม่จองผ่าน LINE → ได้ใบรับจอง **ไม่มี QR** · กลุ่มแอดมินได้การ์ดพร้อมปุ่ม · ชีตสถานะ `สั่งจอง` · สต็อกลด
2. กดปุ่มยืนยันอันเดิมซ้ำ → **ไม่เกิดออเดอร์ที่สอง**
3. พิมพ์ `ชั่ง OD0000xx 4.2` ในกลุ่มแอดมิน → ลูกค้าได้ยอดจริง + QR ยอดเดียวกับในชีต · สถานะ `รอชำระเงิน`
4. พิมพ์ `ชั่ง ...` ในกลุ่มอื่น / แชตลูกค้า → ไม่ทำงาน
5. ลูกค้าส่งสลิป → `slip_submitted` (ยังไม่ confirmed) · กลุ่มได้รูปสลิป + ปุ่ม · กด ✅ → `ชำระเงินแล้ว/เตรียมจัดส่ง`
6. ใส่เลขพัสดุในหน้าแอดมิน → สถานะไม่เด้งกลับ (ยืนยันว่า deploy ข้อ 0 แล้ว)
7. ยกเลิกออเดอร์ → สต็อกคืน
8. จองผ่านเว็บ → หน้าสำเร็จไม่มี QR · หลังบ้านเห็นออเดอร์ในแท็บที่ถูก
9. ลากบอทเข้ากลุ่มใหม่แล้วพิมพ์ข้อความ → การ์ดออเดอร์ใหม่ **ไม่ไป** กลุ่มนั้น
10. แจ้งเคลมด้วย `เคลม OD0000xx` และด้วยเลขล้วน → หาออเดอร์เจอ เคลมบันทึกเลขเต็ม
